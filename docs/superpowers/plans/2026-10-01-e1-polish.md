# E1 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-screen browser titles, a home-screen icon with manifest and theme colour, screen-reader announcements and heading fixes, the E2/D follow-ups, designed empty states on ~20 lists, and every checkbox/radio as a full `label.check` row — one PR, no frozen text changed.

**Architecture:** One `page_title` helper feeding both layouts; static icon assets rendered once from one SVG and committed; a single `shared/_empty_state` partial (card or one-line variant) used at each site inside the existing containers; a mechanical `label.check` conversion per form. Everything is ERB, vanilla CSS with tokens, and i18n in seven locales.

**Tech Stack:** Rails 8 ERB, vanilla CSS/JS, RSpec (helper, view, request, node-run script specs, layout specs via `spec/support/layout_measurement.rb`), chrome-headless-shell for rendering the icon PNGs.

**Spec:** `docs/superpowers/specs/2026-10-01-e1-polish-design.md` — read it alongside this plan; the spec wins where they differ, except the rulings below.

**Plan-level rulings (deviations from the spec, deliberate):**
1. **No duplicate action links where the page already has the button.** Dashboard «Мои игры» already shows «Создать игру» under the list and the game page already shows the add-level button, so their empty states carry text only — a second link would duplicate the control (and the level CTA text «Добавить новое задание» is frozen-negative for some viewers, `features/levels/create-level.feature:20,25`). The teams list keeps its «Создать команду» link (no existing button there).
2. **`game_run` messages become whole sentences, not attribute nouns.** Gender agreement between a noun and rails-i18n's generic predicates is not achievable in uk/be/pl for this noun, and `game`'s own `max_team_number` already uses sentence messages with `format: "%{message}"`. `game_run` follows the same pattern (its `starts_at` already does) — `spec/i18n_sentence_messages_spec.rb` enforces that every message under such a format is a sentence.
3. **The invalid checkbox rule is `.field label.check:has(.is-invalid)`**, not `.field > label.check.is-invalid`: a hand-written `<label class="check">` never passes through `FieldErrorMarkup`, which marks the *input* (`is-invalid`, `aria-invalid`) and appends a `.field-error` span after it.
4. **Five machine-produced locales.** ru and en values are given verbatim below; uk/be/pl/tr/ka are produced by the implementer following CLAUDE.md's policy (natural wording, interpolation variables identical, Turkish/Georgian never put a case suffix on a `%{placeholder}`, gender agreement in uk/be/pl). Each file already carries its "machine-translated" header comment.

```ruby
  # The browser-tab title, most specific first so a phone's narrow tab shows
  # what matters: "Page — Game · Site", any part omitted when absent. A view
  # calls page_title once; the layouts call page_title_text. Game names are
  # author-written and arrive verbatim -- the layout's <%= %> escapes them.
  def page_title(page = nil, game: nil)
    @page_title_parts = { :page => page.presence, :game => game&.name.presence }
    nil
  end

  def page_title_text
    parts = @page_title_parts || {}
    head = [ parts[:page], parts[:game] ].compact.join(" — ")
    [ head.presence, t("layout.title") ].compact.join(" · ")
  end
```

In both layouts replace `<title><%= t("layout.title") %></title>` with `<title><%= page_title_text %></title>`.

  // Must equal --bg in tokens.css for each theme; spec/theme_script_spec.rb
  // reads both files and fails if they drift.
  function themeColorFor(theme) { return theme === "light" ? "#faf8f6" : "#12100e"; }

  if (typeof document === "undefined") {

    var meta = document.querySelector('meta[name="theme-color"]');
    if (meta) meta.setAttribute("content", themeColorFor(theme));
  }

  var stored = null;
  try { stored = localStorage.getItem("theme"); } catch (e) { /* private mode */ }

  var prefersLight = window.matchMedia &&
                     window.matchMedia("(prefers-color-scheme: light)").matches;

  var initial = stored || (prefersLight ? "light" : "dark");
  document.documentElement.setAttribute("data-theme", initial);
  applyThemeColor(initial);

  window.toggleTheme = function () {
    var next = document.documentElement.getAttribute("data-theme") === "dark" ? "light" : "dark";
    document.documentElement.setAttribute("data-theme", next);
    applyThemeColor(next);
    try { localStorage.setItem("theme", next); } catch (e) { /* ignore */ }
  };
})();
