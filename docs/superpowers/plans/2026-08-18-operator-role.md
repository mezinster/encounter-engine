# Operator Role Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second privileged role, `operator`, that a superadmin can grant and revoke — the column, the predicates, the console controls and the audit trail — without granting it any authority yet.

**Architecture:** One boolean column on `users`, mirroring `is_superadmin`. Two predicates on `User`: `operator?` reading the column, and `may_operate_commercial?` ORing it with `superadmin?`. Two member actions on the existing `Admin::UsersController`, siblings of its `grant`/`revoke`, behind the same `require_superadmin!` filter and calling the same `record_admin_action`. Two console view changes. Seven i18n keys across seven locale files.

**Tech Stack:** Rails 8.0, Ruby 3.3.12 (rbenv), RSpec (request + model specs), sqlite in dev/test, YAML locale files.

**Spec:** `docs/superpowers/specs/2026-08-18-operator-role-design.md`
**Programme umbrella:** `docs/superpowers/specs/2026-08-18-commercial-games-programme-design.md`

require "rails_helper"

  let(:ordinary)   { create_user }
  let(:superadmin) { u = create_user; u.update!(:is_superadmin => true); u }
  let(:target)     { create_user }

  end

  it "refuses an anonymous visitor" do
    post grant_operator_admin_user_path(target)

    expect(response).to have_http_status(:found)
    expect(response).to redirect_to(login_path)
    expect(target.reload.operator?).to be false
  end

    sign_in(ordinary)

    post grant_operator_admin_user_path(target)

    expect(response).to have_http_status(:unauthorized)
    expect(target.reload.operator?).to be false
  end

  # operators; only a superadmin can.
  it "refuses an operator who is not a superadmin" do
    operator = create_user
    operator.update!(:is_operator => true)
    sign_in(operator)

    post grant_operator_admin_user_path(target)

    expect(response).to have_http_status(:unauthorized)
    expect(target.reload.operator?).to be false

  it "grants the role for a superadmin" do
    sign_in(superadmin)

    post grant_operator_admin_user_path(target)

    expect(response).to redirect_to(admin_user_path(target))
    expect(target.reload.operator?).to be true

  it "revokes the role for a superadmin" do

    target.update!(:is_operator => true)
    sign_in(superadmin)

    post revoke_operator_admin_user_path(target)

    expect(target.reload.operator?).to be false

- [ ] **Step 5: Add the controller actions**

In `app/controllers/admin/users_controller.rb`, after `#revoke` ends (currently `:51`) and before the `#destroy` comment block:

```ruby
  # The operator role (sub-project A of the commercial-games programme). It
  # grants nothing yet: its authority clause lands in sub-project B, where
  # Game#commercial? will exist to scope it.
  #
  # No self guard and no last-holder guard, unlike #revoke above. Both of that
  # method's guards exist so the instance can never end up with nobody able to
  # administer it; a superadmin can always grant this role back, so neither
  # applies. See docs/superpowers/specs/2026-08-18-operator-role-design.md, D4.
  #
  # record_admin_action is called AFTER the change lands, matching the rule in
  # AdminAudit: a refused action must leave no entry.
  def grant_operator
    user = User.find(params[:id])
    user.update!(:is_operator => true)
    record_admin_action("grant_operator", user)
    redirect_to admin_user_path(user), :notice => t("admin.users.operator_granted_notice")
  end

  def revoke_operator
    user = User.find(params[:id])
    user.update!(:is_operator => false)
    record_admin_action("revoke_operator", user)
    redirect_to admin_user_path(user), :notice => t("admin.users.operator_revoked_notice")
  end
```
